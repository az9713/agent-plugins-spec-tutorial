    1 · The canonical identifiers

    FileRequired $schema value for 1.0.0

    Three rules about these strings
    1. A client selects local rules from the value. It never fetches the URL during a load §5.2.
    2. The version in mcp.json must match the version in plugin.json §10.1.
    3. A published identifier is never reassigned to different schema contents §10.1.

    4 · mcp.json — all keys

    4.1 Top level

    KeyRequiredTypeNote
    $schemaYesstringVersion must match plugin.json.
    mcpServersYesobjectAn empty object is valid.

    No other top-level key is permitted. A violation disables MCP for the whole plugin §7.2.2.

    4.2 The three closed variants

    Keystdiostreamable-httpsseExpands
    typeRequiredRequiredRequiredNo
    commandRequired——No
    argsOptional——Yes
    envOptional——Values only
    cwdOptional——Yes
    url—RequiredRequiredNo
    headers—OptionalOptionalNo

    A key from another variant, or any unknown key, invalidates that one entry §7.2.1.

    4.3 Value rules

    FieldLegal values
    commandOne token: a bare executable name, or a ./ path inside the plugin root. Never a shell string.
    cwdExactly three forms: ./…; ${PLUGIN_ROOT} or ${PLUGIN_ROOT}/…; ${PLUGIN_DATA} or ${PLUGIN_DATA}/…. Default: the plugin root.
    envString values only. The keys PLUGIN_ROOT and PLUGIN_DATA are forbidden.
    urlAbsolute http or https. No user information. No fragment. Plain http only for localhost or a loopback IP literal.
    headersString values. Case-insensitive names, and no duplicate name under different casing. Never a credential.

    7 · The two canonical schemas

    7.1 plugin.schema.json

    jsonschemas/1.0.0/plugin.schema.json
    {
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "title": "Agent Plugins Manifest",
  "type": "object",
  "properties": {
    "$schema": { "const": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json" },
    "name": {
      "type": "string",
      "minLength": 1,
      "maxLength": 64,
      "pattern": "^(?!.*(?:--|\\.\\.))[a-z0-9](?:[a-z0-9.-]*[a-z0-9])?$"
    },
    "version": { "type": "string" },
    "description": { "type": "string" },
    "author": {
      "type": "object",
      "properties": {
        "name": { "type": "string" },
        "email": { "type": "string" },
        "url": { "type": "string" }
      },
      "additionalProperties": false
    },
    "homepage": { "type": "string" },
    "repository": { "type": "string" },
    "license": { "type": "string" },
    "keywords": { "type": "array", "items": { "type": "string" } },
    "extensions": { "type": "object", "additionalProperties": { "type": "object" } }
  },
  "required": ["$schema", "name"],
  "additionalProperties": false
}

    7.2 mcp.schema.json

    jsonschemas/1.0.0/mcp.schema.json — abridged
    {
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "type": "object",
  "properties": {
    "$schema": { "const": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json" },
    "mcpServers": { "type": "object", "additionalProperties": { "$ref": "#/$defs/server" } }
  },
  "required": ["$schema", "mcpServers"],
  "additionalProperties": false,
  "$defs": {
    "server": {
      "oneOf": [
        { "$ref": "#/$defs/stdioServer" },
        { "$ref": "#/$defs/streamableHttpServer" },
        { "$ref": "#/$defs/sseServer" }
      ]
    },
    "stdioServer": {
      "type": "object",
      "properties": {
        "type": { "const": "stdio" },
        "command": { "type": "string", "minLength": 1 },
        "args": { "type": "array", "items": { "type": "string" } },
        "env": {
          "type": "object",
          "propertyNames": { "not": { "enum": ["PLUGIN_ROOT", "PLUGIN_DATA"] } },
          "additionalProperties": { "type": "string" }
        },
        "cwd": {
          "type": "string",
          "pattern": "^(?:\\./|\\$\\{PLUGIN_ROOT\\}(?:/|$)|\\$\\{PLUGIN_DATA\\}(?:/|$))"
        }
      },
      "required": ["type", "command"],
      "additionalProperties": false
    }
  }
}
    The schema is not the whole contract

    The specification text is authoritative when it conflicts with a schema §5.2, §7.2.1. JSON Schema cannot express path containment, single-token command resolution, expansion order, or the failure boundaries. A validator alone does not make a client conformant.

    8 · Glossary

    TermMeaning
    PluginA self-contained directory with a manifest and optional components §3.
    Plugin rootThe top-level directory of the package.
    ManifestThe file plugin.json at the plugin root.
    ComponentA skill, or an MCP server entry. Version 1 defines these two only.
    ClientA tool that discovers, installs, loads, and runs plugin components.
    Extension namespaceA reverse-domain identifier that one client owns.
    Extension directoryA top-level directory named exactly after an extension namespace.
    Closed schemaA schema that permits a fixed key set. An unknown key is a violation.
    Failure boundaryThe narrowest unit that a failure may disable: the plugin, one component type, or one entry.
    Streamable HTTPThe current MCP remote transport.
    HTTP+SSEThe deprecated MCP 2024-11-05 remote transport, selected by "type": "sse".

    9 · Conformance language

    In the normative sections, MUST, MUST NOT, REQUIRED, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL carry their RFC 2119 and RFC 8174 meaning, and only when they appear in capitals §2.

    Appendix A and the Design Decisions section of the specification are non-normative. Every other section is normative §2.
